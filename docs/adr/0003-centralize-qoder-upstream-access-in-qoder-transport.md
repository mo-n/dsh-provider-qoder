# Centralize Qoder upstream access in Qoder transport

All Qoder upstream communication is owned by one deep Qoder transport module rather than a public generic HTTP client; its interface exposes only model streaming, model discovery, and account reading. Each transport instance binds one immutable service region, model catalogs are configured and persisted separately by region, and a region switch replaces the active instance while allowing already-started requests to finish. Shared reads use last-waiter cancellation, only idempotent metadata reads may retry internally, DSH continues to own model-generation retries, and connection pools, background refresh, circuit breakers, dynamic rate limiting, and full tracing remain out of scope until demonstrated needs justify them.
