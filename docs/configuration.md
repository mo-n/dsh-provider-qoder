# 插件配置

在启用插件的 DSH profile YAML 中，找到已有的 `dsh-provider-qoder` 条目，在其 `config` 下填写配置；不要为修改配置重复添加插件条目。

```yaml
- id: provider-qoder
  name: dsh-provider-qoder
  config:
    modelQueueMaxWaitMs: 3600000 # 60 分钟
```

## Qoder 模型排队等待上限

`modelQueueMaxWaitMs` 设置单次逻辑模型调用的累计排队等待上限，单位为毫秒。同一调用多次进入排队时共用此上限，不会在每次恢复后重新计时。它不是整个对话回合的总时限，也不包含正常生成内容的耗时。

| 项目 | 规则 |
| --- | --- |
| 默认值 | `3600000`，即 60 分钟 |
| 有效范围 | `1` 至 `2147483647` 的整数 |
| 示例 | 10 分钟为 `600000`；30 分钟为 `1800000` |
| 非法值 | 拒绝配置；`0` 不表示无限等待或关闭排队 |
| 恢复默认 | 删除此字段 |

配置经 DSH 加载生效后，新发起的模型调用使用新上限；已开始的调用保留原上限。若编辑 YAML 后 DSH 未自动加载变更，请重载对应 profile 或重启 DSH。

设置页面不提供此字段的编辑入口，也不提供对应的环境变量。以前通过设置页面保存的同名配置值继续有效，无需迁移。修改时保留该插件条目下的其他配置。

排队状态面板展开后的“等待上限”以秒显示该调用实际使用的上限；“排队数量”“预计等待”和服务可用状态来自 Qoder 服务端，与本地设置的等待上限不同。达到上限后，该调用以排队超时结束；用户也可以提前停止等待。
